каждый пункт привязан к этапу, где он становится важен.

- Зафиксировать в плане этапа 2 семантику склейки: какие поля вакансии «побеждает первый»,
  какие расширяются при склейке (гео уже расширяется: `[]`/`None` = без ограничений побеждает).

  присваивается без `greatest` (ревью судьи PR #1, P2).

  `location_restrictions` — только страны; пустой список читается как «без ограничений»
  (ревью судьи PR #1, P2).

## До этапа 4 (GitHub Actions + Neon)

- **Himalayas:** обход упирается в `max_pages` каждый день (200 записей, ~50–65 dev за 3 дня
  не помещаются); теперь это честный `degraded: truncated`, но полноты нет. Порядок выдачи —
  новые сверху, кроме закреплённых. Перейти на `/jobs/api/search?sort=recent` или поднять
  `max_pages`.
- Тест CLI `fetch`: User-Agent/таймаут доходят до клиента, коды выхода по матрице §6.7.
- Публичные логи: ошибки уровня fetch (`describe_error`) — в одну строку и без сторонних значений;
  первая строка сообщения psycopg для некоторых ошибок может содержать входное значение.
- Нет `DATABASE_URL` → сейчас трейсбек pydantic; нужно понятное сообщение на русском.
- Миграции гонять через direct-эндпоинт Neon, не `-pooler`.
- Защита тестовой БД проверяет только имя `*_test` — удалённая база с таким именем будет очищена.
- Advisory lock / `concurrency` против одновременного локального и cron-прогона. Кроме
  конфликта уникального индекса: два прогона с разными source ID одной вакансии создадут два
  `jobs`, а параллельное расширение гео может потерять одно из обновлений.
- Лимит размера HTTP-ответа (JSON/XML/HTML) против memory/CPU DoS со стороны источника.
- Закрепить экшены CI на SHA, когда в workflow появятся секреты.
- Тест на враждебный XML (billion laughs / внешняя сущность) → источник `failed`, не падение.

## Когда понадобится источник, которому это важно (RemoteOK, v2 ATS)

- `canonical_url`: URL без схемы превращается в мусор; порт по умолчанию не убирается;
  `_DROP_PARAMS` выкидывает общие `source`/`src`/`u`.
- URL-шаг дедупа игнорирует компанию (общая страница карьеры склеила бы разные роли).
  Две разные вакансии одной компании с одинаковым заголовком за 60 дней всегда склеятся.
- `fetch_feeds` вызывает `key()` вне per-feed `try`; записи без id/guid схлопываются в один ключ.
- Himalayas: разбор страницы 2+ вне `try`; страница без `pubDate` останавливает обход;
  «все смещения» по усечению `int()` — эвристика (точная проверка: `set(range(-11, 15)) <= set(offsets)`).
- Himalayas: при смене формата (`parentCategories` пропал) источник покажется `empty`, а не `degraded`.

## Косметика / тесты, по случаю

- Стоп-слова из 2 букв («in», «of», «qa») считаются маркерами → «Engineer in Test» и
  «Engineer Test» не склеятся (консервативно, намеренно).
- Не все формы гендерных пометок убираются («(m/w/divers)», «[all genders]») — только пропуск склейки.
- WWR: навыки делятся по голому « and » («Machine Learning and AI» → два тега).
- Недостающие тесты: `make_engine`, round-trip `%` в `alembic_config`, downgrade, дробные
  смещения часовых поясов, смешанные даты в lookback, `call_count` в тесте нескольких индустрий Jobicy.
- Нет `server_default` у NOT NULL колонок (важно только для не-ORM писателей); нет индекса на
  `source_runs.run_id`.
